Section 01

Reference Architecture (Vision Rev 2)

Every Create product is built on the pattern that shipped in vision/index.html. The 1.0 spec described Vision as designed; this one describes Vision as built, which is stricter and better. Engineers replicate exactly this.

1.1 — The pattern

  1. One HTML file. Markup, CSS and JS in one file. External: PeerJS (jsDelivr), optionally qrcode-generator, Google Fonts. No build step, no bundler, no framework.
  2. A stable device code. On first run the browser gives itself a six-letter code from the alphabet ABCDEFGHJKMNPQRSTUVWXYZ23456789; it is the PeerJS id (create-<prefix>-<code>) and never changes, so two devices that have met reconnect by themselves.
  3. Two people, A and B. S.me is 'a' or 'b'; names live in S.names. If both devices think they are A, the one that joined moves to B. Multi-person products add a people map and the hub pattern.
  4. Per-field last-writer-wins. Every synced record carries _t, a stamp per field. Merge takes the newer stamp field by field; a record never replaces another whole.
  5. hello, then put. The first message on a connection carries the whole state; after that only changed items travel. Product-level fields (names, settings) travel as meta.
  6. Let a new device in. A hello from a device the product has not paired with is held until the user accepts it. After that the device is remembered as the partner.
  7. Soft deletes. del: true is a field like any other; nothing is ever removed from items.
  8. localStorage, one key. create.<id>.v1, written debounced, with a full-storage toast rather than a crash. Other pages leave work in create.<id>.inbox.
  9. Backup without a server. A JSON file; a deflate-raw link when the state is small; product exports (CSV, .ics, printable pages).
  10. Offline first. With no PeerJS and no network the product does everything but sync, and says so in one line.

1.2 — What this means for engineering

Do not over-architect. The code structure, naming and sync logic should be recognizable to anyone who has read Vision. The build brief that engineers (and the agents that build Wave 1) follow is news/create/apps/BUILDING.md; it is the normative short form of sections 2–5 below, with the test hooks the harness drives.

P2P Layer — Protocol v2

This is Vision's wire protocol, generalized. Products change only the prefix, the shape of hello's product fields, and (for hub products) how many connections they keep.

3.1 — Identity and the signaling server

const ALPH = 'ABCDEFGHJKMNPQRSTUVWXYZ23456789';
const code6 = () => { const a = new Uint32Array(6); crypto.getRandomValues(a); return [...a].map(x => ALPH[x % ALPH.length]).join(''); };
const PID = c => 'create-prc-' + String(c).toLowerCase();          // Practice; each product has its own prefix

function peerOpts() {                                               // ?peer=127.0.0.1:9000 → a self-hosted PeerJS server (tests, intranets)
  const q = new URLSearchParams(location.search).get('peer');
  if (q) { const [h, p] = q.split(':'); return { host: h, port: +p || 9000, path: '/', secure: location.protocol === 'https:', debug: 0 }; }
  return { debug: 0 };
}

3.2 — Start, dial, wire

let peer = null, net = 'idle', netMsg = '';
const conns = new Set(), openConns = () => [...conns].filter(c => c.open);

function startPeer() {
  if (!S || peer) return;
  if (!window.Peer) { setNet('nolib', 'The sync library didn’t load. Everything else works; you can still back up as a file.'); return; }
  setNet('starting');
  try { peer = new Peer(PID(S.dev), peerOpts()); } catch (e) { peer = null; setNet('error', 'Sync couldn’t start in this browser.'); return; }
  peer.on('open', () => { setNet(S.partner || S.pending ? 'dialing' : 'ready'); if (S.partner) dial(S.partner.code, true); if (S.pending) dial(S.pending); });
  peer.on('connection', c => wire(c, false));
  peer.on('disconnected', () => { if (!openConns().length) setNet('offline', 'Lost the matchmaking server. Trying again…');
    setTimeout(() => { if (peer && !peer.destroyed && peer.disconnected) try { peer.reconnect(); } catch (e) {} }, 4000); });
  peer.on('close', () => { peer = null; });
  peer.on('error', e => { if (e.type === 'peer-unavailable') { netMsg = 'Your partner’s device isn’t open right now.'; setNet(S.partner ? 'away' : 'ready'); }
                           else if (e.type === 'unavailable-id') { /* this code is open in another tab */ } else setNet('error', 'Sync hit a problem: ' + e.type); });
}
function dial(code, auto) {
  if (!peer || peer.destroyed || peer.disconnected || code === S.dev) return;
  if (openConns().some(c => c.peer === PID(code))) return;
  if (!auto) setNet('dialing');
  wire(peer.connect(PID(code), { reliable: true, metadata: { v: 1 } }), true, code);
}
function wire(c, outgoing, code) {
  conns.add(c); c._hello = false; c._sent = false;
  c.on('open', () => { if (outgoing) { c._sent = true; send(c, hello()); } paint(); });   // the dialer speaks first
  c.on('data', d => { try { onMsg(c, d, outgoing, code); } catch (e) { console.warn('bad message', e); } });
  c.on('close', () => { conns.delete(c); if (!openConns().length) setNet(S.partner ? 'away' : 'ready'); paint(); });
  c.on('error', () => { conns.delete(c); paint(); });
}
const send = (c, m) => { try { if (c.open) c.send(m); } catch (e) {} };

3.3 — Messages

// hello: the whole state, once per connection, from the dialer first
{ t:'hello', v:1, dev:S.dev, me:S.me, joined:!!S.joined, name: myName(), names:S.names, meta: productMeta(), items:S.items }
// put: the items that changed (the whole item, with its _t)
{ t:'put', items:[ { id, …, del, _t:{…} } ] }
// meta: product-level fields with their own stamps (names, settings, a board title)
{ t:'meta', names:S.names, _t:S._t }
// chunk: a large message in pieces (products on the chunked pattern)
{ t:'chunk', id, i, n, data }
function onMsg(c, d, outgoing, code) {
  if (!d || typeof d !== 'object') return;
  if (d.t === 'hello') {
    if (d.dev === S.dev) return;                                         // my own other tab
    const known = S.partner && S.partner.code === d.dev;
    if (!known && S.partner && !outgoing && !c._ok) { pendingAsk = { c, d }; askAccept(d); return; }   // a device we haven't seen
    acceptHello(c, d, outgoing); return;
  }
  if (!c._hello) return;                                                 // nothing counts before hello
  if (d.t === 'put' && Array.isArray(d.items)) { const ch = d.items.filter(mergeItem); if (ch.length) { save(); render(true); relay(c, ch); } }
  else if (d.t === 'meta') { if (mergeMeta(d)) { save(); render(true); } }
  else if (d.t === 'chunk') { const whole = chunkIn(d); if (whole) onMsg(c, whole, outgoing, code); }
}
function acceptHello(c, d, outgoing) {
  c._ok = true;
  let wait = false, swapped = false;
  if (d.me === S.me) { const yieldMe = S.joined && !d.joined ? true : !S.joined && d.joined ? false : S.dev > d.dev; if (yieldMe) { swapSlots(); swapped = true; } else wait = true; }
  S.partner = { code: d.dev, at: Date.now() }; S.pending = null;
  if (!wait) { mergeMeta(d); for (const it of Object.values(d.items || {})) mergeItem(it); S.joined = false; }
  save(true); c._hello = true;
  if (!c._sent || swapped) { c._sent = true; send(c, hello()); }
  setNet('on'); render(true);
}
function broadcast(items) { if (!items.length) return; const m = { t:'put', items: items.map(it => S.items[it.id] || it) }; for (const c of openConns()) if (c._hello) send(c, m); }

PeerJS signaling

PeerJS Cloud brokers the WebRTC handshake and nothing more. Once connected, data flows browser to browser; if the server goes away, open connections continue and the product retries registration every four seconds. ?peer=host:port points a product at a self-hosted server (the test harness runs one on 127.0.0.1:9000).

4.1 — The state object

const KEY = 'create.practice.v1';
let S = null;
function blankState(me) {
  return { v:1, dev: code6(), me, joined:false, partner:null, pending:null, names:{ a:'', b:'' }, _t:{},
           /* product fields, e.g. */ pursuits:{}, items:{}, created: Date.now() };
}
const LS = { get(k, d) { try { const v = localStorage.getItem(k); return v == null ? d : JSON.parse(v); } catch (e) { return d; } },
             set(k, v) { try { localStorage.setItem(k, JSON.stringify(v)); return true; } catch (e) { return false; } } };

function save(now) {
  clearTimeout(saveT);
  const go = () => { if (S && !LS.set(KEY, S) && !saveWarned) { saveWarned = true; toast('This browser’s storage is full. Remove a photo or two so it can save.'); } };
  if (now) go(); else saveT = setTimeout(go, 120);
}
function load() { const s = LS.get(KEY, null); if (!s || s.v !== 1) return migrate(s); S = Object.assign(blankState('a'), s); return true; }

4.2 — Stamps and merge

let lastStamp = 0; const SALT = Math.floor(Math.random() * 90) + 10;
function stamp() { const t = Math.max(Date.now(), Math.floor(lastStamp / 100) + 1); lastStamp = t * 100 + SALT; return lastStamp; }
const seeStamp = n => { if (n > lastStamp) lastStamp = n; };             // never issue a stamp below one we've seen

function setF(it, f) { const t = stamp(); for (const k of Object.keys(f)) { it[k] = f[k]; it._t[k] = t; } return it; }
function create(id, f) { const it = { id, _t:{} }; setF(it, f); S.items[id] = it; return it; }
const live = () => Object.values(S.items).filter(it => !it.del);

function mergeItem(r) {
  if (!r || !r.id) return false;
  for (const v of Object.values(r._t || {})) seeStamp(v);
  const L = S.items[r.id];
  if (!L) { S.items[r.id] = JSON.parse(JSON.stringify(r)); return true; }
  let ch = false;
  for (const k of Object.keys(r._t || {})) if ((r._t[k] || 0) > (L._t[k] || 0)) { L[k] = r[k]; L._t[k] = r._t[k]; ch = true; }
  return ch;
}

The Inbox Handoff

Products never call each other. A page that has something for a product appends an entry to that product's inbox array in localStorage; the product drains it the next time it is open (and immediately, if it is open in another tab, through the storage event). Section 06

Pictures — Resize and Chunking

function readPicture(file, maxSide = 1024) {
  return new Promise((ok, no) => {
    if (file.size > 2 * 1024 * 1024 * 4) return no(new Error('That picture is very large; try a smaller one.'));
    const img = new Image(); img.onload = () => {
      const s = Math.min(1, maxSide / Math.max(img.width, img.height));
      const c = document.createElement('canvas'); c.width = Math.round(img.width * s); c.height = Math.round(img.height * s);
      c.getContext('2d').drawImage(img, 0, 0, c.width, c.height);
      const out = c.toDataURL(file.type === 'image/png' ? 'image/png' : 'image/jpeg', 0.82);
      URL.revokeObjectURL(img.src);
      out.length > 2 * 1024 * 1024 ? no(new Error('Still over 2 MB after resizing.')) : ok(out);
    }; img.onerror = () => no(new Error('That file isn’t a picture.')); img.src = URL.createObjectURL(file);
  });
}

const CHUNK = 128 * 1024, chunkBuf = {};
function sendBig(c, m) {                                   // any message whose JSON is over 200 KB
  const s = JSON.stringify(m); if (s.length < 200 * 1024) return send(c, m);
  const id = uid(), n = Math.ceil(s.length / CHUNK);
  for (let i = 0; i < n; i++) send(c, { t:'chunk', id, i, n, data: s.slice(i * CHUNK, (i + 1) * CHUNK) });
}
function chunkIn(d) {
  const b = chunkBuf[d.id] = chunkBuf[d.id] || { n: d.n, parts: [], got: 0 };
  if (!b.parts[d.i]) { b.parts[d.i] = d.data; b.got++; }
  if (b.got < b.n) return null;
  delete chunkBuf[d.id]; return JSON.parse(b.parts.join(''));
}

Section 08

Hub Pattern (Form, Pool, Gift, Trip)

The two-person code path already keeps conns as a set. A hub product sets S.role to 'host' on the device that created the group and 'guest' on devices that joined by its code. Guests dial only the host; the host accepts each guest once (the same accept step as a partner) and keeps every connection.

function relay(from, items) {                              // host only: what one guest put goes to every other guest
  if (S.role !== 'host') return;
  const m = { t:'put', items };
  for (const c of openConns()) if (c !== from && c._hello) send(c, m);
}
// a guest that comes back later gets the whole state in the host's hello, including what other guests added meanwhile
// if the host is away, guests keep working on their own copies and reconcile when it returns (per-field stamps make this safe)

Trust. The host is a relay, not an authority: it merges by stamps like everyone else. Products that need an authority (Pool's lock times) enforce the rule on the host and mark late picks as late rather than dropping them.

async function deriveKey(passphrase, salt) {
  const material = await crypto.subtle.importKey('raw', new TextEncoder().encode(passphrase), 'PBKDF2', false, ['deriveKey']);
  return crypto.subtle.deriveKey({ name:'PBKDF2', salt, iterations:600000, hash:'SHA-256' }, material, { name:'AES-GCM', length:256 }, false, ['encrypt', 'decrypt']);
}
async function seal(key, obj) { const iv = crypto.getRandomValues(new Uint8Array(12));
  const ct = await crypto.subtle.encrypt({ name:'AES-GCM', iv }, key, new TextEncoder().encode(JSON.stringify(obj))); return { iv: b64(iv), blob: b64(ct) }; }
async function open(key, e) { return JSON.parse(new TextDecoder().decode(await crypto.subtle.decrypt({ name:'AES-GCM', iv: unb64(e.iv) }, key, unb64(e.blob)))); }

Sync. Only { id, iv, blob, del, _t } travels; both devices must know the passphrase. A blob that arrives before the local vault is unlocked is stored as-is and decrypted on demand; if the passphrase differs the entry shows as “from your other device (locked)”.

Section 10

Hidden Claims (Gift)

Every device holds every field — that is what makes sync simple — but the device of the person a list is for never renders claimedBy, claimedAt, chipIns, ideas about them, or Secret Santa pairs other than their own. The mask is a render rule, not a storage rule:

const mine = it => it.owner === S.meId;
function claimView(it) { return mine(it) ? null : { by: it.claimedBy, at: it.claimedAt, chipIns: it.chipIns || [] }; }   // null → draw nothing

Trust boundary

v1 is trust-based: a determined list owner could read the storage of their own browser. The product says so under Settings → About. A v2 could encrypt claim fields to the non-owners' keys; it is not planned until someone asks.

Section 15

API Bridge — Future Layer

Pre-design (Wave 4 or later)

A separate, optional component — never embedded in a product. A REST-like JSON endpoint a product can be pointed at as a secondary sync target beside P2P, for the case where two devices are never open at once. Planned as a Cloudflare Worker or Deno Deploy function that stores only what a product chooses to send (for Vault and Net, ciphertext). P2P stays primary and default; no product will ever require the bridge.
